# Конструктор курсов

SPA + REST API по «Архитектуре 4.0»: React (Vite) + Express + SQLite (Prisma).

Инструкция для пользователя (как работать с приложением: курсы, блоки, тесты,
темы, печать) — `Инструкция.txt` в корне проекта.

## Запуск

### Windows: одним двойным щелчком

В корне проекта лежат два файла:

- `Запустить сервер.bat` — проверяет Node.js (нужен 20 или новее), при первом
  запуске ставит зависимости в `client` и `server` (`npm install`), готовит
  Prisma Client (`npx prisma generate`, если `server/node_modules/.prisma/client`
  ещё нет), создаёт `server/.env` из `.env.example`, если его нет, при отсутствии
  `server/prisma/dev.db` применяет миграции (`prisma migrate deploy`) и заливает
  демо-данные (`npm run db:seed`), затем открывает два окна консоли — API
  (`npm run dev`, порт 4000) и Vite (`npm run dev`, порт 5173) — и, дождавшись
  ответа `http://localhost:5173`, открывает страницу в браузере;
- `Остановить сервер.bat` — завершает процессы `node.exe` на портах 4000 и 5173
  (останавливает только приложение) и закрывает служебные окна.

Занятые порты определяются через `netstat -ano` без ключа `-p tcp`: Vite слушает
IPv6 (`[::1]:5173`), а `-p tcp` показывает только IPv4. Поэтому повторный запуск
не поднимает второй экземпляр — просто открывает уже работающее приложение.
Служебные окна консоли закрывать нельзя: это и есть сервер.

Ручной порядок ниже нужен для Linux/macOS или если батник не подходит.

### Перенос на другой компьютер

Папку `node_modules` переносить нельзя: Prisma Client генерируется на каждой
машине отдельно (внутри лежит бинарный query engine), а нативные модули вроде
`bcrypt` собираются под конкретную версию Node. Скопируйте проект без
`node_modules` (и без `dist`), затем запустите `Запустить сервер.bat` — он сам
поставит зависимости, сгенерирует Prisma Client, создаст `server/.env`, при
необходимости применит миграции и засеет демо-данные. Для первого запуска нужен
интернет.

Если папку всё же скопировали вместе с `node_modules` и API падает с
`SyntaxError: The requested module '@prisma/client' does not provide an export
named 'PrismaClient'` (а Vite при этом пишет `proxy error ... ECONNREFUSED`),
удалите `server/node_modules` и `client/node_modules` и запустите батник снова.

Данные приложения лежат в `server/prisma/dev.db` (курсы, блоки, пользователи) и
`server/uploads/` (загруженные файлы) — их можно скопировать отдельно, чтобы
перенести контент.

```bash
# 1. Бэкенд (терминал 1)
cd server
npm install
npm run prisma:migrate   # создаёт dev.db по схеме
npm run db:seed          # пользователь admin (пароль — в server/prisma/seed.js) + глобальные темы
npm run dev              # http://localhost:4000

# 2. Клиент (терминал 2)
cd client
npm install
npm run dev              # http://localhost:5173
```

Дев-сервер Vite проксирует `/api` на `http://localhost:4000`, поэтому CORS в разработке не мешает.
Переменные окружения: `server/.env` (см. `.env.example`) и `client/.env` (`VITE_API_URL=/api`).
Адрес API для прокси можно переопределить переменной `API_PROXY_TARGET` (по умолчанию
`http://localhost:4000`), а таймаут чтения на сервере — `REQUEST_TIMEOUT_MS`.

Вход в приложение: кнопка «Войти, как читатель» — `POST /api/auth/guest` выдаёт сессию роли
`reader` (только чтение, запись отдаёт 403), либо логин/пароль редактора через `POST /api/auth/login`.
Логин и пароль на странице входа не показываются.

### Если вместо страницы — 502 Bad Gateway

`502` отдаёт не API, а прокси Vite: Express на `:4000` не запущен, перезапускается или упал.
Порядок действий:

1. Откройте `http://localhost:4000/api/health`. `{"status":"ok","database":"ok"}` — API в порядке;
   `503` и `"database":"unavailable"` — процесс жив, но база не открылась (проверьте
   `server/.env`, `DATABASE_URL` и `npm run prisma:migrate`).
2. Если `:4000` не отвечает вовсе — запустите API (`Запустить сервер.bat` или `npm run dev`
   в `server/`). Клиент перезапускать не нужно: прокси подхватит API сам.
3. Если в консоли API `SyntaxError: ... does not provide an export named 'PrismaClient'` —
   см. примечание про перенос `node_modules` выше.

Что в проекте сделано, чтобы `502` не пугал:

- прокси Vite (`client/vite.config.js`) при ошибке upstream отвечает `503` с JSON
  `{"message":"Сервер временно недоступен. Повторите попытку."}` и заголовком
  `Retry-After: 2` вместо пустой страницы `502 Bad Gateway`;
- `/api/health` проверяет базу (`SELECT 1`): `200` только когда данные доступны, иначе
  `503` + `Retry-After` — видно, что сломалось именно соединение с базой;
- ошибки Prisma «база недоступна/занята» (`P1001`, `P1002`, `P1008`, `P1017`, `P2024`,
  `P2028`) отдают `503` вместо `500`, подробности пишутся в консоль сервера;
- зависшее чтение обрывается через `REQUEST_TIMEOUT_MS` (15 с) ответом `503`, а не висит
  до таймаута браузера; запись не обрывается, чтобы повтор не создал дубликат;
- API поднимается даже с нерабочей базой и честно отвечает `503`, порт занят — короткое
  сообщение вместо стектрейса, при остановке (`SIGINT`/`SIGTERM`) соединения закрываются
  аккуратно;
- клиент (`client/src/api/axios.js`) ждёт ответ 20 с, сам повторяет GET при
  `408/425/429/500/502/503/504` и сетевых сбоях (две попытки) и заменяет технический
  текст axios на понятный: «Сервер временно недоступен…», «Сервер не ответил вовремя…»,
  «Нет связи с сервером…»;
- тест (`TestReader`) на такую ошибку показывает спокойную плашку с подсказкой и кнопкой
  «Повторить», красный алерт остаётся для ответов сервера (4xx).

## Модалки

Модалка открывается через стор интерфейса: `useUiStore.getState().openModal('course-create')`,
`openModal('course-edit', course)`, `openModal('course-delete', course)`, `openModal('block-create', { courseId })`,
`openModal('block-edit', block)`, `openModal('block-delete', block)`, `openModal('block-help', block)`. Рендерит их `ModalHost` в `App.jsx`:
базовый `ui/Modal.jsx` (портал, Esc, клик по фону, блокировка прокрутки), поверх — `course/CourseModal.jsx`,
`block/BlockSettingsModal.jsx`, `block/HelpModal.jsx` (Правка 7) и `ui/ConfirmModal.jsx`. Мутации `courseStore`/`blockStore` возвращают
`{ ok, message, fieldErrors }`, поэтому ошибки валидации сервера попадают в поля формы, а не в общий алерт страницы.

## Порядок элементов (reorder)

Перестановка везде устроена одинаково: `PUT /api/<сущность>/reorder` с полным списком id —
`{ orderedIds }` у курсов (верхний уровень) или `{ courseId | blockId | slideId, orderedIds }` у блоков,
слайдов теории, контента, групп, вопросов, слайдов и карточек памятки. У карточек памятки
в теле `blockId` и `slideId` — порядок проверяется внутри одного слайда. Тело запроса — не diff, а **новое состояние порядка
коллекции**, поэтому метод `PUT`, а не `PATCH`: операция идемпотентна (повтор даёт тот же результат),
а `reorderItems` в `utils/order.js` одной транзакцией проставляет `order = индекс в массиве`. Ответ —
200 с обновлённой коллекцией, клиент берёт порядок из ответа, а не из своего состояния.

`validateOrder` (там же) требует, чтобы список содержал все существующие id **ровно по одному разу**:
дубликат или пропуск → 400 (`missingIds`). Без этой проверки «забытые» элементы сохраняли бы старый
`order` и получали коллизии с переставленными.

## Блоки

Страница курса (`/course/:id`) грузит курс (`courseStore.fetchCourse`) и его блоки (`blockStore.fetchBlocks`)
и состоит из двух областей: слева — поиск по названию и карточки блоков (кнопка «Начать» / «Продолжить» /
«Сначала» по прогрессу), справа — превью выбранного блока с обложкой и затемнением снизу. Режим редактора
добавляет меню настроек курса (⚙️: добавить блок, загрузить блок, редактировать курс, скачать курс, создать
тему) и меню блока (⋮: редактировать, скачать, дублировать, удалить). `BlockSettingsModal` принимает обложку
ссылкой или файлом — выбор, drag&drop и вставка из буфера, загрузка идёт через `POST /api/files`. API:

- `GET /api/blocks?courseId=` — блоки курса по `order` (без `courseId` → 400);
- `GET /api/blocks/:id`, `POST /api/blocks`, `PUT /api/blocks/:id`, `DELETE /api/blocks/:id`;
- `PUT /api/blocks/reorder` — `{ courseId, orderedIds }`, транзакция в `utils/order.js`;
- `GET /api/blocks/:id/export` — JSON-манифест блока в формате `course.json` архива курса;
- `POST /api/blocks/import` — multipart `file` + `courseId`: файл блока (JSON) или ZIP с `course.json`;
- `POST /api/blocks/:id/duplicate` — копия блока со всем содержимым в конце курса.

Импорт проверяет тот же валидатор, что и архивы (`readBlockManifest` → `normalizeBlock`), а запись идёт
через `createBlockRecord` — тот же код, что у импорта курса; картинки не копируются, ссылки `/uploads/...`
должны существовать на сервере.

Тип блока (`theory | test | memo | glossary`) проверяется на сервере; менять тип можно только пока блок пустой —
иначе 400 и `errors.type` (то же правило отражает `BlockSettingsModal`, блокируя выбор типа). Удаление курса
удаляет блоки каскадом, удаление блока — его контент. Все мутации пишутся в `AuditLog` (`entity: 'Block'`).

## Теория: слайды и контент

Страница блока (`/block/:id`) грузит блок (`blockStore.fetchBlock`) и показывает редактор по типу
(`TheoryBlock` — через `lazy`, остальные типы — заглушка `BlockPlaceholder`). API слайдов и контента:

- `GET /api/slides?blockId=` — слайды блока вместе с `contents` и `contentCount`;
- `POST /api/slides` (`{ blockId, title? }`), `PUT /api/slides/:id` (`{ title }`), `DELETE /api/slides/:id`;
- `PUT /api/slides/reorder` — `{ blockId, orderedIds }`;
- `GET /api/contents?slideId=` — контент слайда по `order`, в ответе всегда `dataVersion`;
- `POST /api/contents` (`{ slideId, type, data?, width? }`), `PUT /api/contents/:id` (`{ data?, width? }`),
  `DELETE /api/contents/:id`, `PUT /api/contents/reorder` — `{ slideId, orderedIds }`.

Слайды и контент доступны только в блоке «Теория»: для остальных типов сервер отвечает 400.
`dataVersion` — константа сервера (`CURRENT_DATA_VERSION = 1` в `server/src/utils/content.js`), клиент её
не присылает: попытка передать `dataVersion` даёт 400. Для `text` и `important` в `data` хранится Tiptap JSON
(проверяется `data.type === 'doc'`), для остальных типов `data` мержится с дефолтной структурой типа.
У «Важного» рядом с документом лежит `data.important` — оформление блока (цвет фона и рамки, толщина,
скругление); сервер нормализует его так же, как клиент (`normalizeImportantStyle`).

`TheoryContent.width` (33 / 50 / 66 / 100) добавлен на Шаге 9: слайд собирается из рядов до 3 колонок
(`buildContentRows` на клиенте, ряд = подряд идущие фрагменты, пока сумма ширин ≤ 100 %). Карточка
сжимается до своей доли ряда (`min-width: 0` в `.content-card`), поэтому три блока по 33 % остаются в
одной строке и в узкой колонке редактора — жёсткий минимум 180px переносил третий блок вниз.

Клиент (`contentStore`): автосохранение текста с задержкой 700 мс, добавление фрагмента через тулбар и
«плюсики», перетаскивание карточек, удаление, изменение ширины колонки, переименование слайда и его
перестановка стрелками в разделе «Содержание». В режиме просмотра (`uiMode = view`) тулбар и действия скрыты,
контент рендерится `ContentRenderer` (текст — собственный рендер Tiptap JSON, остальные типы — просмотр/плеер),
а карточки теряют рамки и подписи типов — слайд читается как единая страница (Правка 9).

Меню «плюсика» (`ContentAdder` в `ContentGrid`) живёт в состоянии React: панель типов скрыта атрибутом `hidden`,
закрывается сразу после выбора типа, а ещё по клику мимо и по Esc. Раньше это был нативный `<details>` — его
открытое состояние оставалось в DOM, и после добавления фрагмента меню «залипало» поверх сетки.

«Плюсик» ряда есть только у ряда, за которым идёт продолжение: он вставляет фрагмент сразу после этого ряда.
У последнего ряда своего «плюсика» нет — вставка «после него» совпадает с добавлением в конец, и в памятке с
глоссарием этот значок стоял под содержимым прямо над нижним «плюсиком», открывая то же меню и делая то же
действие. Поэтому внизу карточки остаётся один «Добавить фрагмент в новый ряд», а отступ под «плюсик»
(`.slide-row--add`) получают только ряды, где он действительно есть.

«Важное» — аккуратный цветной блок с рамкой, как alert, но без иконки-маркера и кнопки закрытия: внутри
только текст. Оформление живёт в `data.important` (см. `utils/important.js`): `background` — цвет фона
(`''` — цвет темы `--color-important`), `borderColor` — цвет рамки (`''` — на 18 % темнее фона), `borderWidth`
1–2 px, `radius` 8–12 px. В редакторе под блоком есть палитра, свой цвет, цвет рамки и селекты толщины и
скругления (`editors/ImportantStyleFields.jsx`); при смене цвета блок перекрашивается сразу, а сохраняется
вместе с документом через автосохранение. Если фон выбирает автор, цвет текста подбирается по яркости
(тёмный на светлом, светлый на тёмном), иначе текст берётся из темы. Tiptap возвращает только
`{ type, content }`, поэтому `withImportantStyle` приклеивает `important` при каждом сохранении текста.
Толщина и скругление уходят инлайном в стиль блока, а цвета по умолчанию рисует CSS из переменных темы
(`--color-important`, `--color-important-border` в `styles/themes.css`), чтобы блок читался и в тёмной теме.
В печати блок сохраняет фон и рамку (`print-color-adjust: exact` в `styles/print.css`).

Тулбар (`components/editor/toolbar/`): отмена/повтор, «Добавить контент» (только теория), стиль текста, шрифт
и размер, цвет текста и выделение, выравнивание, группа «Списки» (маркированный, нумерованный, уровни,
настройка многоуровневого списка), «Ссылка» (Правка 6) и «Примечание» (Правка 5). Поиск по документу — Шаг 17.

Правка 3: панель инструментов одна на блок и есть во всех типах блоков — в теории она форматирует текст
слайда, в тесте — пояснение к вопросу, в памятке — текст карточки, в глоссарии — определение термина.
Кнопки применяются к тому rich-text полю, где стоит курсор: `TiptapEditor` регистрирует себя в
`store/editorStore.js` при монтировании и фокусе и освобождает ссылку при размонтировании, а `Toolbar`
берёт активный экземпляр оттуда. Панель закреплена сверху (`position: sticky; top: 8px`) и остаётся на
экране при прокрутке, как в Word; пока ни одно поле не в фокусе, справа видна подсказка «Нет активного
текстового поля».

Правка 4: списки стали многоуровневыми, как в Word. Уровней до девяти (глубже — оформление повторяет девятый):
`Tab` понижает уровень, `Shift+Tab` повышает, `Enter` создаёт следующий пункт того же уровня, `Backspace` в
пустом пункте выводит его из списка — это штатный `ListKeymap` из StarterKit. Номера в тексте не хранятся:
`utils/listNumbering.js` считает их из структуры (`1.`, `2.`, `2.1.`, `2.1.1.`), поддерживает форматы
`1 / a / A / i / I`, шаблон с подстановками `%1…%9` (например, `%1.%2` или `%4)`), суффикс, отступ уровня и
начальный номер. Счётчики живут внутри одного верхнего списка (`listId`), поэтому списки нумеруются
независимо, а настройки уровней лежат в атрибуте `levels` самого списка — у каждого списка может быть свой
формат. В редакторе номера рисует плагин декораций (`components/editor/extensions/multiLevelList.js`): в DOM
попадают `data-list-label` и `--list-indent`, CSS выводит маркер через `li::before`: он прижат к тексту
справа (`right: 100%`), поэтому длинный номер (`1.2.1.`) растёт влево, в отступ, и не наезжает на текст пункта.
Просмотр и печать считают номера тем же алгоритмом (`annotateListNumbering` в `ContentRenderer`), поэтому
редактор, режим чтения и печать совпадают. Явный `bulletList` всегда показывает символ маркера, так что
смешанные списки (номера и маркеры на разных уровнях) работают как в Word. Настройка — кнопка
«Многоуровневый список» в группе «Списки» (`toolbar/ListGroup.jsx`, окно `toolbar/MultiLevelListDialog.jsx`):
9 строк с типом уровня, форматом номера, шаблоном, суффиксом, отступом и стартом.

Правка 5: примечания к тексту, как в Wiki. Автор выделяет слово или фразу и нажимает «Примечание» (облачко на
панели, `Ctrl+Alt+M`), вводит короткое пояснение (до 300 символов) и сохраняет — над словом появляется номер
верхним индексом, а само слово получает пунктирное подчёркивание в акцентном цвете темы. В режиме чтения
номер и слово открывают всплывающую подсказку с текстом и кнопкой «×» (плашки «Примечание N» нет — только
само пояснение), закрытие по Esc или клику вне окна; на телефоне подсказка открывается тапом. Клик по слову
или номеру в редакторе, а также кнопка «Примечание» при курсоре внутри примечания открывают то же поле с
кнопкой «✕ Удалить». Примечания работают у всех типов контента: у «Текста» и «Важного» это метка Tiptap, у
таблицы, чек-листа, картинки, видео, кода и реплики — `data.notes` (`{ id, text, field, ref, from, to, word }`),
а у поля появляется номер-кнопка и облачко для создания примечания (`components/content/editors/RichInput.jsx`).

Номера в тексте не хранятся: `utils/notes.js` считает их по порядку появления (`collectNotes`, `annotateNotes`,
`plainNoteNumbers`) и сквозняком по слайду — `collectSlideNotes` отдаёт смещение каждого фрагмента
(`offsetById`), его получают `TiptapEditor` (storage плагина) и `ContentRenderer`/печать (`noteOffset`),
поэтому после удаления или добавления примечания в другом фрагменте номера пересчитываются сами. В редакторе
номер рисует плагин декораций (`components/editor/extensions/inlineNote.js`): метка — mark `inlineNote` с
`noteId` и `text`, а номер — виджет `span.inline-note__mark` сразу после последнего вхождения метки, поэтому
разметка редактора и режима чтения совпадает. Попаппер — `toolbar/NoteGroup.jsx` и `toolbar/NotePopover.jsx`
(общий для Tiptap и обычных полей, связь через `store/noteStore.js`), подсказка — `components/content/NoteTip.jsx`,
текст с примечаниями в обычных полях — `components/content/RichText.jsx`. Печать выводит метки и номера
чёрным (`.print-doc .inline-note` в `print.css`).

Правка 6: ссылки. Автор выделяет слово и нажимает «Ссылка» (звено цепи на панели, `Ctrl+K` или правый клик →
«Добавить ссылку»), в диалоге (`toolbar/LinkDialog.jsx`) выбирает внешнюю ссылку (адрес, «Открыть в новой
вкладке») или внутреннюю — дерево курса «блок → слайды / вопросы / карточки памятки / термины». Можно изменить
текст ссылки. Дерево отдаёт `GET /api/courses/:id/links` (`server/src/utils/linkMap.js`), оно кешируется
на курс в `store/linkStore.js`.

Внутренняя ссылка хранит готовый путь `/block/<id>?slide=…` и описание цели, поэтому просмотр рисует подсказку
«Ведёт на: Тест → Вопрос 2», не загружая карту курса. В тексте ссылка выглядит как подчёркнутое слово — без плашек
и меток типа. В редакторе ссылка подчёркнута, при наведении появляется иконка звена цепи, клик открывает диалог,
`Ctrl+Shift+K` удаляет. В Tiptap это расширение `extensions/courseLink.js` с атрибутами `linkKind/targetType/targetId/
targetBlockId/targetLabel/targetBadge/newTab`; у обычных полей ссылки лежат в `data.links` (`{ id, field, ref, from,
to, word, kind, href, … }`) рядом с `data.notes`. Обе аннотации раскладывает общий модуль `utils/plainText.js`,
а рисует `components/content/RichText.jsx` — слово может быть и ссылкой, и примечанием одновременно.

В просмотре переход выполняет `components/content/useInternalLink.js`: блок открывается с нужным слайдом
(`?slide=`), вопросом (`?question=`), карточкой памятки (`?memo=`) или термином (`?term=`) и подсвечивает цель;
в шапке появляется кнопка «← Назад» (`components/layout/BackLink.jsx`), история переходов — в `linkStore`.
Печать выводит внутреннюю ссылку подчёркнутым текстом, без перехода. Ссылки доступны во всех типах контента.

Правка 7: справка о блоке. На странице блока в правом верхнем углу — круглые кнопки: палитра («Темы
оформления»), шестерёнка («Настройки блока», только редактору) и знак вопроса («Справка о блоке»).
Справка открывается в модалке `components/block/HelpModal.jsx`: дата последнего изменения, список сносок
(примечаний, Правка 5) с номерами, текстом и местом и раздел «Упоминается в» — где блок упоминается по
внутренним ссылкам (Правка 6) из других блоков курса.

Данные собирает `GET /api/blocks/:id/help` (`routes/blockRoutes.js` → `controllers/helpController.js` →
`server/src/utils/help.js`). Модуль чистый: `collectDocNotes`, `collectPlainNotes`, `collectBlockNotes`
разбирают метки `inlineNote` и `data.notes`, `collectDocLinks`, `collectPlainLinks`, `collectBlockMentions`
ищут ссылки на блок в других блоках (свои ссылки не считаются), `blockPlaces` переводит слайд, вопрос,
карточка памятки и термин в адрес `?slide=`, `?question=`, `?memo=`, `?term=`, `blockUpdatedAt` берёт максимум из даты
блока и дат фрагментов теории, а `buildBlockHelp` нумерует сноски и ограничивает ответ `HELP_LIMIT = 300`
(текст обрезается до 300 символов). Клиент не кеширует ответ: `store/helpStore.js` запрашивает справку при
каждом открытии, поэтому она всегда актуальна.

В режиме редактирования сноска — кнопка: клик ведёт к слайду, вопросу, карточке памятки или термину через
`useInternalLink` и запоминает место в истории «← Назад». В режиме чтения сноски выводятся текстом (без
переходов), а упоминания остаются ссылками на блоки. Пустые разделы пишут «Примечаний нет» и
«Нет упоминаний»; ошибка загрузки показывается алертом с кнопкой «Повторить».

Правка 8: код как в VS Code. Фрагмент «Код» оформлен тёмной панелью с жёлобом номеров строк:
`components/content/CodeSurface.jsx` рисует `<pre>` с номерами (одним текстовым узлом, а не
тысячами `<span>`) и полотно, `utils/code.js` считает строки, готовит номера и заменяет
недопустимый NUL пробелом. Редактор (`editors/CodeEditor.jsx`) держит жёлоб на одной линии с
textarea: `wrap="off"`, Tab по-прежнему вставляет два пробела, а `onScroll` синхронизирует
прокрутку. В просмотре (`CodeView` в `ContentRenderer.jsx`) та же панель, язык и имя файла —
в тёмной шапке. Цвета фиксированные (`#1e1e1e`, жёлоб `#252526`), поэтому код читается одинаково
в светлой и тёмной теме.

Безопасность: код выводится только текстовыми узлами React — ни `dangerouslySetInnerHTML`,
ни `eval`. Поэтому `<script>`, `</code>` и обработчики вроде `onerror` остаются видимыми
символами и не превращаются в разметку. Сервер (`normalizeContentData`) меняет NUL на пробел
той же длины, чтобы DOM не ломался, а позиции примечаний и ссылок не съезжали. В печати тёмный
фон заменяется белым с чёрным текстом, номера строк скрываются — иначе перенос длинных строк
разъедет жёлоб.

Правка 9: бесшовный просмотр. В режиме чтения карточка фрагмента больше не рисует рамку, фон и
шапку с типом: `SlideGrid` добавляет класс `content-card--view` и не выводит `content-card__head`,
а CSS убирает у карточки `border`/`background` и `padding` тела. Цветной блок «Важного» остаётся —
это собственный блок фрагмента (`.content-important`), а не подложка карточки. В редактировании
разметка прежняя — шапка с иконкой, шириной колонки и удалением. Подсветка найденного фрагмента
(`content-card--found`) в просмотре сохраняется.

Правка 10: интерактивный чек-лист. В режиме читателя пункты отмечаются настоящими чекбоксами:
клик ставит галочку, зачёркивает текст и подсвечивает пункт светло-зелёным (`#e8f5e9`), повторный
клик возвращает обычный вид. Состояние хранит `utils/checklistProgress.js` в localStorage по ключу
`course-builder:checklist:<blockId>` (в JSON только отмеченные пункты), поэтому прогресс
восстанавливается после перезагрузки. В списке блоков курса у блока с сохранёнными отметками
появляется кнопка «Сначала» (`BlockCard` → `resetChecklistProgress`), она очищает все чекбоксы
блока. В редактировании и печати чек-лист остаётся авторским: там нет `checklistBlockId`,
поэтому показывается сохранённое в контенте поле `checked` и обычные некликабельные квадраты.

## Контент слайда: редакторы Шага 10

У каждого типа контента своя форма в `components/content/editors/`; все изменения уходят через
`useAutoSave` (700 мс, статус «Сохраняем… / Сохранено / Не удалось сохранить», последняя правка
отправляется при уходе с карточки):

- **Картинка** — drag&drop или выбор файла, вставка готовой ссылки (или Ctrl+V из буфера), alt, подпись,
  ширина 10–100 % и выравнивание в колонке, изменение размера мышью за восемь ручек, «Сохранять пропорции»,
  обрезка, интерактивные маркеры и рамки выделения (прямоугольник, круг, треугольник, стрелка — с
  перемещением, изменением размера, поворотом, цветом, заливкой и контуром). Загрузка идёт в
  `POST /api/files`, в `data` сохраняются `fileId` и `url`;
  подробности — в разделе «Картинка: маркеры, обрезка, пропорции и рамки выделения» ниже;
- **Видео** — drag&drop или выбор файла mp4/webm/ogg (до 200 МБ), ссылка YouTube (`watch`, `youtu.be`,
  `shorts`, `embed`, `live`), Vimeo или прямой файл; плеер показывается сразу и в редакторе, и в просмотре
  (`getVideoEmbed` в `utils/helpers.js` понимает и загруженные `/uploads/...`). Ширина видео — это ширина
  колонки из шапки карточки (33/50/66/100 %), причём карточка видео не растягивается на весь ряд
  (`.content-card--video { flex-grow: 0 }`), поэтому выбранный процент виден и у одинокого видео.
  Карточка всегда стоит на своём месте в ряду, а «Выравнивание в колонке» (`data.align`: left / center /
  right) работает внутри колонки, как у картинки: плеер занимает всю колонку, к краю прижимается
  содержимое (подпись). Раньше `data-align="center"` задавал `margin: auto` самой карточке, и видео
  «улетало» в середину ряда;
- **Таблица** — до 6 колонок и 30 строк; ячейка — Tiptap-документ, поэтому внутри работают жирный,
  курсив, цвет, размер шрифта, списки, ссылки и примечания (панель инструментов блока форматирует ту
  ячейку, где стоит курсор). Клик по ячейке открывает ввод, Tab / Shift+Tab и стрелки переходят между
  ячейками, выделение диапазона — мышью, Shift+кликом или Shift+стрелками, Delete очищает выделенные
  ячейки. «Объединить» / «Разделить» работают как в Google Таблицах (если в других ячейках есть текст —
  подтверждение), «Скопировать» и «Вставить из буфера» обмениваются данными с Excel и Google Таблицами
  (TSV), вставка сама расширяет таблицу в пределах лимитов;
- **Чек-лист** — заголовок, 1–2 столбца, до 100 пунктов, перемещение пунктов и отметка «выполнено»;
  в режиме читателя пункты отмечаются кликом и сохраняются в localStorage (Правка 10);
- **Код** — язык (JavaScript, TypeScript, Python, Java, C#, SQL, HTML, CSS, Bash, JSON, plaintext),
  имя файла и текст с Tab = два пробела; редактор и просмотр — тёмная панель как в VS Code с
  номерами строк, в шапке просмотра язык, имя файла и копирование кода (Правка 8); код всегда
  выводится текстом, без исполнения HTML;
- **Диалог** (тип в базе — `replica`) — сцена из нескольких реплик (до 20): у каждой своё имя персонажа,
  аватар (PNG/SVG; без картинки — первая буква имени), сторона на слайде (слева / по центру / справа,
  горячие клавиши Ctrl+Shift+L / E / R) и место персонажа (авто / слева / справа / сверху / снизу).
  Оформление сцены общее: размер аватара 40–240 px, цвет облачка и рамки (или «как в теме»), толщина
  рамки, скругление, хвостик и его направление, выравнивание текста. «+» под репликами добавляет новую,
  внизу — предпросмотр (`DialogView`), он же рендер слайда; примечания и ссылки работают как в других типах.

### Таблица: данные, миграция и буфер обмена

Ячейка таблицы хранится как Tiptap-документ, поэтому у неё ровно те же возможности, что у фрагмента
«Текст»:

```js
data = {
  columns: 3,
  rows: 2,
  headerRow: true,
  // каждая ячейка — Tiptap-документ того же формата, что data у типа «Текст»
  cells: [[{ type: 'doc', content: [{ type: 'paragraph', content: [{ type: 'text', text: 'Шаг' }] }] }, …], …],
  // объединение помнит только верхняя левая ячейка диапазона
  merges: [{ row: 0, col: 0, rowSpan: 1, colSpan: 2 }],
}
```

- примечания и ссылки ячейки — метки `inlineNote` и `link` внутри документа: отдельных
  `data.notes` / `data.links` у таблицы больше нет. Нумерация примечаний сквозная по слайду —
  `collectContentNotes` обходит ячейки построчно, `TableView` считает смещение для каждой ячейки;
- объединённая ячейка рисуется одним `<td>`/`<th>` с `rowSpan`/`colSpan`, текст закрытых ячеек
  очищается (остаётся только в верхней левой) — как в Google Таблицах. Объединение, «выходящее»
  за пределы выделения, запрещено, иначе соседние ячейки разорвались бы;
- старые таблицы (строки + `data.notes`/`data.links` с диапазонами `from`/`to`) переводятся в новый
  формат автоматически: `normalizeTableData` на клиенте и `normalizeTable` на сервере разносят
  аннотации по словам и ставят метки, а слово при расхождении диапазона ищется заново по `word`;
- редактор держит смонтированным один Tiptap — `editors/CellEditor.jsx` у той ячейки, которую
  правят; остальные ячейки рисует `ContentRenderer` (`DocContent`). Поэтому панель инструментов,
  ссылки (`Ctrl+K`) и примечания (`Ctrl+Alt+M`) работают без отдельного тулбара таблицы;
- буфер обмена — TSV: `tableToTsv` копирует таблицу, `pasteMatrix` раскладывает вставку по сетке,
  расширяя её до нужного размера в пределах лимитов (`CONTENT_LIMITS.tableRows/tableColumns`);
- `utils/table.js` — чистые функции таблицы (выделение, объединение/разделение, изменение размеров,
  TSV, навигация). Их проверяют `check:editor` (клиент) и `check:table` (сервер).

### Картинка: маркеры, обрезка, пропорции и рамки выделения

```js
data = {
  fileId: 'clx…',
  url: '/uploads/scheme.png',
  alt: 'Схема этажа',
  caption: 'План этажа',
  width: 60,          // ширина в колонке, %
  align: 'left',      // left | center | right
  lockAspect: true,   // «Сохранять пропорции»
  aspect: null,       // свободные пропорции: высота / ширина (null — натуральные)
  crop: null,         // обрезка: { x, y, w, h } в долях исходника
  // маркеры — те же data.notes, что у примечаний, но с координатами в процентах
  notes: [{ id: 'note-1', text: 'Серверная комната', field: 'marker', x: 25, y: 40, … }],
  // рамки выделения: фигуры поверх картинки в процентах от видимой области
  shapes: [
    { id: 'shape-1', type: 'rect', x: 10, y: 20, w: 30, h: 15,
      rotation: 0, color: '#E03131', fill: 20, stroke: 2 },
  ],
  links: [],
}
```

- маркер — примечание с `field = 'marker'` и точкой `x`/`y` (проценты от видимой области
  картинки), поэтому номера сквозные по слайду (`plainNoteNumbers`), подсказка рисуется общим
  `NoteTip`, а «Справка о блоке» показывает маркеры через `collectPlainNotes` →
  `collectBlockNotes` без отдельных правил;
- `utils/image.js` — чистые функции картинки: `collectImageMarkers`, `createImageMarker`,
  `addImageMarker`, `setImageMarkerText`, `removeImageMarker`, `moveImageMarker`, `normalizeCrop`,
  `cropImageStyle`, `imageFrameRatio`, `clampImageWidth`. Маркер без текста не хранится: сервер
  отбрасывает примечания с пустым `text`, поэтому пустой черновик просто не сохраняется;
- обрезка хранится долями, а не пикселями: `cropImageStyle` растягивает картинку внутри рамки, а
  `imageFrameRatio` считает CSS `aspect-ratio` рамки из натуральных пропорций и `crop`. Поэтому
  обрезка одинакова в колонке, в печати и на любом экране (натуральные пропорции приходят из
  `onLoad` картинки, до загрузки обрезка не применяется);
- свободные пропорции — `aspect` (высота / ширина): при выключенных пропорциях ширина меняется
  ручкой, высота — отдельной; при включении галочки `aspect` сбрасывается в `null`;
- ширина ограничена 10–100 % (`clampImageWidth` в клиенте и `asInt(data.width, 10, 100, 100)` на
  сервере), координаты маркеров — 0–100 % с одним знаком после запятой (`normalizeMarkerPoint`);
- просмотр в полном размере — `ImageLightbox` в `ContentRenderer`: двойной клик по картинке или
  кнопка-лупа, закрытие по «×», клику по фону и Esc (прокрутка страницы на время просмотра
  блокируется);
- рамки выделения — `data.shapes`: прямоугольник, круг, треугольник и стрелка (`type`), положение и
  размер в процентах (`x`, `y`, `w`, `h`), `rotation` (−180…180), цвет в HEX, `fill` — прозрачность
  заливки 0–100 %, `stroke` — контур 0–4 px. Фигуры рисуются общим `content/ImageShapes.jsx`
  (SVG `viewBox="0 0 100 100"` + `preserveAspectRatio="none"` и `vector-effect: non-scaling-stroke`,
  поэтому контур остаётся пиксельным), поэтому редактор и просмотр/печать выглядят одинаково;
- редактор: «Добавить рамку» открывает меню фигур, фигура рисуется мышью на картинке (минимум 3 %
  по каждой стороне), тянется за центр, меняет размер за углы и поворачивается за кружок; у
  повёрнутой фигуры углы тянутся вдоль её осей, а противоположный угол остаётся на месте;
  Delete удаляет выбранную рамку, Esc отменяет рисование. Оформление — в панели «Рамки выделения»:
  палитры «Цвета темы» (активная тема) и «Цвета системы» (фиксированный набор с названиями),
  заливка и контур. Цвета нормализуются в `#RRGGBB`, лимит — 20 рамок (`IMAGE_SHAPES_LIMIT`);
- `utils/image.js` также хранит `normalizeShape`/`collectImageShapes`/`updateImageShape`,
  `rectFromPoints` и `shapeTitle` — строку списка вида «Прямоугольник (красный)»;
- `check:render` проверяет разметку маркеров, рамок и редактора, `check:image` — серверную
  нормализацию маркеров, обрезки, пропорций, рамок и справку о блоке.


Загрузка файлов — единственный новый API Шага 10:

- `POST /api/files` — `multipart/form-data`, поле `file`, только `admin | editor`: картинки PNG/JPEG/WebP/GIF/SVG
  до 5 МБ или видео MP4/WebM/OGG до 200 МБ; сохраняет файл в `server/uploads` и запись `File`, отвечает
  `{ file: { id, url, mimeType, size } }`, где `url = /uploads/<файл>`; у видео в `data` сохраняется только `url`;
  SVG перед записью в БД чистится `sanitizeSvgFile` (скрипты, `on*`-обработчики, `javascript:`-ссылки),
  а статика `/uploads` отдаёт SVG с `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'`;
- `DELETE /api/files/:id` — удаляет запись и файл с диска (используется вручную/сервисно; при замене картинки
  или видео в редакторе старый файл остаётся, чтобы не ломать общие ссылки);
- `GET /uploads/<файл>` — статика Express (в Vite проксируется через `/uploads`).

Сервер нормализует `data` каждого типа (`normalizeContentData` в `server/src/utils/content.js`):
строки/числа приводятся к ожидаемым типам, `cells` таблицы — к размеру `rows × columns` и к
ячейкам-документам (старые строки с `data.notes`/`data.links` переносятся в метки, `merges`
обрезаются по границам и не пересекаются), `items` — к `{ id, text, checked }`, ширина картинки
ограничена 10–100 %, `crop` приводится к долям 0–1, `aspect` — к числу или `null`, маркеры
(`notes` с `field = 'marker'`) получают координаты 0–100 %, положение видео — только
`left | center | right` (по умолчанию `center`), язык — списком допустимых.


## Блоки Шага 11: тест, памятка, глоссарий

`BlockPage` выбирает редактор по типу блока: `TheoryBlock`, `TestBlock`, `MemoBlock`, `GlossaryBlock`
(все — ленивые чанки); неизвестный тип показывает `BlockPlaceholder`. В режиме чтения
(`uiMode = view` или роль `reader`) те же компоненты рендерят контент без форм и кнопок.

**Тест** (`components/editor/TestBlock.jsx`, `components/test/`)

Два принципиально разных интерфейса: читатель и редактор. `TestBlock` только выбирает
режим (`uiMode === 'edit'` и роль редактора) и загружает данные в `testStore`.

- **Редактор** (`TestEditor`) — вертикальный список белых карточек со скруглением и тенью,
  как в Google Forms, без слайдов и без таймера/прогресс-бара. Сверху — панель базовых
  настроек (`TestSettingsPanel`): тумблеры «Перемешивать вопросы», «Перемешивать варианты»,
  «Режим ветвления», управление группами (добавить, переименовать, удалить) и импорт/экспорт
  CSV с предпросмотром. Внизу списка — форма «Добавить вопрос» с выбором типа.
- **Карточка вопроса** (`QuestionCard`): текст, варианты с радио/чекбоксами и кнопкой
  «Добавить вариант» (до 12), пары «Понятие ↔ Значение» с перетаскиванием (порядок задаёт
  верный ответ) и «Добавить пару», пояснение на розовом фоне. Тип «Карточка» показывает обе
  стороны сразу — «Передняя сторона» и «Задняя сторона» с текстом и картинкой
  (`POST /api/files`), без пояснения. Карточку тянут целиком, как фрагменты в теории
  и карточки памятки: ручки-грипа нет, порядок уходит в `PUT /api/questions/reorder`.
  Поля ввода, кнопки и Tiptap перетаскивание не начинают — из них можно выделять текст,
  а пары внутри вопроса продолжают двигаться своим грипом.
- **Правая панель настроек** (`QuestionSettingsPanel`) открывается только кнопкой-шестерёнкой
  в шапке карточки, а не кликом по самой карточке: тип вопроса, группа, раздел, «Логика
  перехода» по каждому варианту ответа («Перейти к следующему вопросу», «Перейти к разделу…»,
  «Отправить форму»), кнопки «Дублировать» и «Удалить». Закрывается повторным нажатием
  на шестерёнку, крестиком, кликом вне панели или `Esc`; выбранный вопрос подсвечивается
  и запоминается в `localStorage` (`utils/testEditorMemory.js`), поэтому при возврате
  из читателя открывается он же.
- **Ветвление** — разделы (`TestSection`) встают между вопросами: кнопка «+ Добавить раздел»
  под карточкой создаёт точку ветвления и сразу относит следующий вопрос к новому разделу.
  В карточке раздела (`SectionCard`) автор задаёт название и «Итоговый комментарий этого пути»
  (Tiptap) — его читатель увидит, закончив маршрут в этом разделе.
- **Читатель** (`TestReader`) — один вопрос на экран: шапка с таймером и прогрессом,
  сетка навигации справа и подвал «Назад / Дальше». Выбор варианта ничего не проверяет —
  это черновик попытки (`run.picks`), который можно менять или снимать; вердикт
  появляется только после кнопки «Готово» в правом нижнем углу вопроса (она неактивна
  без выбора, а после отправки варианты блокируются). Пары сопоставления собираются
  без оценки и пересобираются кликом по понятию, карточка отправляет ответ двумя
  круглыми кнопками-контурами (крестик — «Не знаю», галочка — «Знаю»; подписей нет,
  текст остался в `aria-label`). Сама карточка — компактный квадратный блок
  (`max-width: 460px`, `aspect-ratio: 1 / 1`) по центру вопроса: изображение живёт
  в медиа-слое (`test-flashcard__media`) и вписывается в него через `object-fit`,
  подпись стоит под картинкой крупным жирным шрифтом, поэтому за рамку ничего не
  выходит. Панель вопроса у типа «Карточка» прозрачная (`test-question--card`):
  рамку и тень несёт сам блок, второй рамки вокруг нет. В правом верхнем углу
  вопроса — флажок «Вернуться позже»
  (`run.flags`): он не связан с ответом и доступен до и после «Готово», помеченная
  ячейка в сетке навигации получает красный треугольник, как флажок в Moodle,
  а под сеткой появляется счётчик меток. Попытка (порядок вопросов и вариантов,
  ответы, черновики, метки, путь, таймер) лежит в `localStorage` — перезагрузка её
  не теряет (`utils/testRun.js`).
- **Ветвление в читателе** — панели навигации нет вообще: перепрыгнуть вопрос нельзя,
  вопросы идут строго по одному, и только ответ выбирает следующий. Шапка показывает
  лишь номер текущего вопроса («Вопрос 3») без общего количества: длина пути зависит
  от ответов. Ответ фиксирует «Дальше» (до выбора кнопка неактивна), а цель берётся
  из варианта (`branchNextId`): раздел, следующий по порядку или «Отправить форму» —
  итог; вопрос, который на пути уже был, пропускается, чтобы читатель не зациклился.
  Пройденный путь хранится в `run.path`, поэтому «Назад» возвращает к предыдущему
  вопросу именно этой ветки. Смена ответа на пройденном вопросе обрезает путь,
  сбрасывает следующие ответы и показывает предупреждение «Ответ изменён — следующие
  вопросы ветки начнутся заново». Итог — раздел, в котором закончился путь: его
  заголовок и «Итоговый комментарий этого пути» идут первым блоком, ниже — разбор
  пройденных вопросов и «Пройти заново» / «К курсу». Флажков «Вернуться позже»
  в ветвлении нет: сетки, где показывается метка, тоже нет.

Автосохранение — `useAutoSave` (700 мс) с проверкой `validateDraft`: неполный черновик
на сервер не отправляется, ошибка показывается под карточкой. Черновик
(`utils/testDraft.js`) хранит и цели переходов вариантов; `sanitizeTargets` превращает
переход в удалённый раздел в «следующий вопрос».

- CSV-импорт вопросов: `вопрос; вариант 1; вариант 2; …; номера верных; пояснение`
  (номера с единицы; один номер → «Один ответ», несколько → «Несколько ответов»; последний столбец
  необязателен). Максимум 100 строк за раз, каждая строка уходит отдельным `POST /api/questions`.
  До импорта модалка (`CsvImportModal`, проп `preview`) показывает первые пять распознанных
  строк: тип, текст, число вариантов/пар и группу. Шаблоны (`TEST_CSV_TEMPLATES`)
  и автоопределение формата — в `utils/csv.js`.


**Памятка** (`MemoBlock`, `components/memo/MemoSlide.jsx`) — слайды с сеткой карточек
(`components/memo/MemoCard.jsx`) и содержание справа, как в теории: на экране один слайд,
остальные открываются из `slide-list`, переключаются «Назад / Далее» (`Navigation`)
и ищутся по документу (`DocumentSearch`, Ctrl+F). Добавление, удаление и порядок
слайдов — в содержании; заголовок слайда сохраняется автосохранением.
Карточка осталась прежней: заголовок и содержимое из фрагментов (текст, картинка,
видео, таблица, важное, код, диалог, чек-лист) с редакторами `ContentEditor` и общей
сеткой `ContentGrid`. Заголовок — такое же форматируемое поле Tiptap (`components/memo/MemoTitle.jsx`):
жирный, курсив, ссылки, цвет и выравнивание работают через общую панель инструментов;
разметка хранится в `MemoCell.titleDoc`, а простой текст дублируется в `title` для поиска.
Между заголовком и содержимым стоит тонкий разделитель `.memo-card__divider` (1px,
`--color-border`, 8–12px воздуха). Внутри слайда карточки лежат сеткой `memo-grid`
(одна колонка на телефоне); в каждом ряду они растягиваются до самой высокой карточки,
а содержимое остаётся прижатым к верху. «Добавить карточку» создаёт новую, стрелки меняют
порядок, корзина удаляет. Новый слайд создаётся сразу с одной пустой карточкой.
Данные: `MemoSlide` (заголовок и порядок) → `MemoCell` (`title`, `titleDoc`, тело). При миграции
старые карточки каждого блока становятся слайдом «Слайд 1», поэтому содержимое не теряется.

**Глоссарий** (`GlossaryBlock`, `components/glossary/TermCard.jsx`) — термин и определение,
поиск по термину и тексту определения (включая нетекстовые фрагменты: подписи картинок и видео,
ячейки таблиц, пункты чек-листа, реплики диалога), импорт CSV `термин; определение`
(`POST /api/terms/bulk`, одна транзакция, до 500 строк). Определение — тоже набор фрагментов
всех типов. В режиме чтения термины идут по алфавиту (`Intl.Collator('ru')`) с заголовками букв;
в редакторе — в порядке создания, чтобы карточка не «уезжала» из-под курсора.

Тело карточки (`client/src/utils/contentBody.js`, `server/src/utils/contentBody.js`) хранится
в том же поле `Json`, что и раньше: `{ version: 2, contents: [{ id, type, width, data }] }`.
Старое определение/текст — один Tiptap-документ — читается как тело из одного текстового
фрагмента, поэтому миграция БД не нужна и данные не теряются.

Общий разбор CSV — `client/src/utils/csv.js` (`parseCsv`, `csvToQuestions`, `csvToTerms`):
разделитель `;`, `,` или табуляция определяется автоматически, поддерживаются кавычки, `""`,
BOM и переводы строк внутри кавычек. Файл читается в браузере, отдельного загрузчика нет.

## Шаг 12: темы оформления

Страница `/themes` (`pages/ThemeEditorPage.jsx`) показывает карточки тем (`components/theme/ThemeCard.jsx`):
глобальные (видны всем) и личные (только свои). В карточке — превью палитры, бейджи

Открывается кнопкой-палитрой в правом верхнем углу шапки (Правка 7); отдельного пункта «Темы»
в навигации нет.
«Копия» открывает форму создания с цветами исходной темы — так из глобальной темы получается
личная, которую можно менять.

Форма (`components/theme/ThemeEditor.jsx`) — название, шесть ролей цвета (`ColorField`:
color-picker + HEX-поле) и палитра «Цвета темы» из 10 цветов; справа живой предпросмотр
(`ThemePreview`). Клиентская проверка `validateThemeDraft` повторяет серверные правила,
ошибки сервера показываются у полей.

`store/themeStore.js` грузит темы после входа (`GET /api/themes`), применяет активную и
переключает её. `applyTheme` из `utils/themes.js` выставляет на `<html>` CSS-переменные
(`--color-primary`, `--color-primary-hover`, `--color-primary-text`, `--color-bg`, `--color-surface`,
`--color-surface-alt`, `--color-border`, `--color-text`, `--color-text-muted`), поэтому вся вёрстка
на переменных меняется сразу; цвет текста на акцентной кнопке подбирается по контрасту
(`contrastText`). При выходе из аккаунта стор сбрасывается, оформление возвращается к
`styles/themes.css`. Палитра «Цвета темы» в тулбаре редактора (`FormatGroup`) берётся из активной темы.

API (все — под `requireAuth`):

- `GET /api/themes` — `{ themes, activeThemeId, defaultThemeId }`; каждая тема отдаётся с правами
  (`isOwn`, `isActive`, `canEdit`, `canDelete`). Пользователь видит глобальные и свои темы, админ — все;
- `POST /api/themes` (`{ name, colors, isGlobal? }`) — личная тема автора; `isGlobal: true` только для
  админа; не более 20 личных тем на пользователя;
- `PUT /api/themes/:id` (`{ name?, colors? }`) — владелец или админ;
- `DELETE /api/themes/:id` — владелец или админ; последнюю глобальную удалить нельзя
  (`User.activeThemeId` обнуляется через `onDelete: SetNull`);
- `PUT /api/themes/active` (`{ themeId }`, `null` → тема по умолчанию) — пишет `User.activeThemeId`;
  выбор темы в аудит не попадает, остальные мутации — `entity: 'Theme'`.

`colors` — `{ accent, muted, background, surface, text, border, themeColors[10] }`, значения только
HEX (`#abc` нормализуется в `#AABBCC`), проверка — `server/src/utils/theme.js::normalizeThemeColors`.
В сиде две глобальные темы — «Классическая» и «Тёмная» (`PRESET_THEMES`).

## Шаг 13: импорт курса из ZIP

На дашборде у редактора есть кнопка «Импорт ZIP»: выбранный файл уходит на
`POST /api/courses/import` (multipart, поле `file`), новый курс добавляется в конец списка.
Ошибка разбора показывается в алерте страницы, успех — счётчиками из `stats`.

Архив — обычный ZIP: `course.json` в корне (или в единственной папке верхнего уровня) и картинки в `files/`.

```json
{
  "format": "course-builder",
  "version": 1,
  "course": { "title": "Название", "description": "Описание" },
  "files": [{ "id": "clx…", "path": "/uploads/abc.png", "name": "files/abc.png", "mimeType": "image/png" }],
  "blocks": [
    {
      "type": "theory",
      "title": "Теория",
      "coverImage": "/uploads/abc.png",
      "slides": [
        { "title": "Слайд", "contents": [
          { "type": "image", "width": 33, "data": { "fileId": "clx…", "url": "/uploads/abc.png" } }
        ] }
      ]
    },
    { "type": "test", "title": "Тест", "groups": [{ "name": "Группа" }],
      "questions": [{ "type": "single", "data": { "text": "…" },
        "options": [{ "text": "4", "isCorrect": true }, { "text": "5", "isCorrect": false }], "groupIndex": 0 }] },
    { "type": "memo", "title": "Памятка", "memoSlides": [
      { "title": "Слайд 1", "cells": [{ "title": "…", "titleDoc": { "type": "doc" }, "body": { "version": 2, "contents": [{ "id": "c1", "type": "text", "width": 100, "data": { "type": "doc" } }] } }] }
    ] },
    { "type": "glossary", "title": "Глоссарий", "terms": [{ "term": "…", "definition": { "version": 2, "contents": [{ "id": "c1", "type": "text", "width": 100, "data": { "type": "doc" } }] } }] }
  ]
}
```

Порядок задают массивы — `order` в архиве нет; вопрос ссылается на группу по `groupIndex`.
`files[].id` и `files[].path` — старые ссылки: картинки сохраняются под новыми именами,
а `fileId`/`url` в контенте и `coverImage` блока заменяются на новые (проверяется в
`smoke-step13`; round-trip «экспорт → импорт» — в `smoke-step14`).

Импорт идёт по алгоритму 2.14: multer держит архив в памяти, `readCourseArchive`
(`server/src/utils/courseArchive.js`) проверяет и нормализует его теми же правилами, что CRUD
(`normalizeContentData`, `normalizeQuestion`, `docFromInput`), и только потом курс, блоки и
содержимое создаются одной транзакцией. Если транзакция откатилась, записанные картинки удаляются.

Лимиты: ZIP ≤ 50 МБ, распакованные данные ≤ 150 МБ, картинка ≤ 5 МБ; до 200 блоков, 500 слайдов,
5000 фрагментов контента, 2000 вопросов, 500 слайдов памятки (до 2000 карточек), 5000 терминов,
500 картинок. Старый архив с плоским `memoCells` читается как один слайд «Слайд 1»;
`titleDoc` у карточки необязателен — без него заголовок берётся из `title`.
Ответы: 201 `{ course, stats }`; 400 — не ZIP, нет `course.json`, битый JSON, версия архива новее
поддерживаемой, пустое название, неизвестный тип блока, содержимое не для этого типа, ссылка на файл
вне архива, невалидный вопрос/`dataVersion`; 403 — не редактор. Аудит — одна запись `Course / create`.

ZIP разбирается `adm-zip` (новая зависимость сервера); распаковка идёт в память, поэтому zip-slip
и запись мусора на диск исключены — имена файлов генерирует сам сервер.

## Шаг 14: экспорт курса в ZIP

У редактора в меню карточки курса есть пункт «Экспорт ZIP»: `GET /api/courses/:id/export`
отдаёт `application/zip` с `Content-Disposition: attachment`, и браузер сохраняет файл без
перезагрузки страницы (`client/src/api/courseExport.js`). Имя файла — название курса
(кириллица передаётся через `filename*=UTF-8''…`, ASCII-дубль — `course.zip`).
Ошибка показывается в алерте дашборда, успех — именем сохранённого файла.

Архив — тот же формат, что читает импорт Шага 13 (`course.json` + `files/`), поэтому
`экспорт → импорт` даёт эквивалентный курс: `smoke-step14` сравнивает манифесты двух
экспортов (без «плавающих» id и даты) и байты картинки.

Сборка архива (`server/src/utils/courseExport.js`) только читает БД: курс загружается одним
запросом с `orderBy` (порядок элементов — порядок массивов), `groupId` превращается в
`groupIndex`, у картинок в манифесте остаются исходные `fileId`/`path`. Имена файлов в архиве
санитизируются (`[A-Za-z0-9._-]`), при совпадении добавляется индекс.

Ответы: 200 — ZIP; 403 — не редактор; 404 — курса нет; 409 — файл из БД отсутствует на диске
(или пустой/больше 5 МБ), превышены лимиты импорта (блоки, картинки, размер архива).
GET в аудит не пишется: журнал фиксирует только изменения данных.

## Шаг 15: печать курса и PDF

Печатная версия курса — отдельная страница `/course/:id/print` без Header и меню
(`client/src/pages/PrintCoursePage.jsx`). Открывается из меню карточки курса
(«Печать / PDF»), из шапки страницы курса и сразу вызывает диалог печати при
`?print=1`; в диалоге браузера документ сохраняется в PDF — кириллица, картинки и
таблицы печатаются его средствами, без PDF-библиотек и встраивания шрифтов.

Данные приходят одним запросом `GET /api/courses/:id/print` — read-model
`server/src/utils/coursePrint.js`: курс, блоки по `order`, слайды с контентом,
вопросы с вариантами и парами, слайды памятки с карточками и термины по алфавиту. Блок
содержит только содержимое своего типа (`toPrintBlock`), поэтому лишние поля не
утекают. Ответы теста помечены `isCorrect`; переключатель «Ответы теста» на
странице убирает отметки верных вариантов, пояснения и обратную сторону карточки.

Документ: титул с названием, описанием и датой, содержание, затем каждый блок с
новой страницы (`break-before: page`). Контент слайда раскладывается теми же
рядами и ширинами, что в редакторе (`buildContentRows`), видео печатается ссылкой
(iframe в PDF бесполезен), пустые фрагменты — короткой пометкой. Стили —
`client/src/styles/print.css` (`@page A4`, белый фон, скрытие панели и кнопок,
`break-inside: avoid` для вопросов, карточек и таблиц).

Ответы: 200 — `{ course, generatedAt }`; 401 — нет токена; 404 — курса нет.
Печатать может и читатель: это просмотр, а не изменение. GET в аудит не пишется,
`Cache-Control: no-store` — перед печатью данные всегда свежие.
Проверки: `smoke-step15` (права, 404, порядок блоков, слайдов, вопросов и
вариантов, алфавит глоссария, изоляция курсов, пустой курс, свежесть, аудит) и
`check:render` (документ, ответы вкл/выкл, «курс не найден», редирект без токена).

## Шаг 16: адаптивность (375 / 768 / 1024)

Новых брейкпоинтов не вводили: используются те же, что и в предыдущих шагах, —
900 (планшет), 640 (телефон), 480 (узкий телефон). Все правила собраны в конце
`client/src/styles/globals.css` в разделе «Шаг 16: адаптивность», чтобы их было
видно вместе, а не по всему файлу.

Что перестраивается:

- курс и список блоков — карточки в одну колонку на 640 (`course-grid`) и 480
  (`block-grid`); теория и тест — боковая панель уезжает под контент на 900;
- слайд — ряд из колонок 33 / 50 / 66 % становится одной колонкой: `slide-row`
  переходит в `flex-direction: column`, а `flex-basis` карточки сбрасывается
  в `auto`, потому что ширина колонки задаётся inline-стилем в `SlideGrid`;
- чек-лист «в две колонки» на телефоне — одна колонка;
- памятка: слайд и содержание — одна колонка на 900, содержание уходит под слайд;
  карточки слайда (`memo-grid`) на 640 складываются в одну колонку;
- панель инструментов редактора закреплена сверху (`position: sticky`) и не переносится в две строки, а
  прокручивается по горизонтали (`overflow-x: auto`) — как и таблицы (`.table-editor`,
  `.content-table-wrap`);
- панель глоссария: поиск занимает всю строку, кнопка импорта остаётся рядом;
- шапка: на 640 скрывается подпись роли, на 480 логин обрезается многоточием,
  чтобы «Выйти» и переключатель режима оставались на месте;
- длинные слова и ссылки переносятся (`overflow-wrap: anywhere`), а код листается
  по горизонтали внутри тёмной панели — номера строк при этом остаются на месте;
  картинки, видео и iframe не шире контейнера (`max-width: 100%`); `overflow-x: hidden`
  на `body` не используется — иначе перестают работать sticky-панели.

Глоссарий получил алфавитный указатель (`GlossaryBlock`): в режиме чтения слева
от терминов стоит колонка букв, по клику страница плавно прокручивается к группе
(`scrollIntoView`, у групп `scroll-margin-top`). На 900 колонка превращается в
горизонтально прокручиваемую строку — это и есть требование «сайдбар →
горизонтальный скролл». В редакторе указателя нет: там термины идут в порядке
создания, чтобы карточка не уезжала из-под курсора.

Печатная версия (`print.css`) на узком экране сжимает поля листа (900: 32/28,
640: 22/16), панель печати переносит заголовок на отдельную строку, а ряды
слайда тоже становятся одной колонкой: `flex-basis: 100% !important` перебивает
inline-ширину. `@page` и `@media print` не менялись — на бумаге по-прежнему A4.

Проверки: `check:responsive` (`client/scripts/responsive-check.mjs`) — 53
статические проверки: viewport, три брейкпоинта, каждая сетка в своей колонке,
памятка: слайд и содержание в одну колонку, карточки слайда в одну колонку, чек-лист 1 колонка, указатель глоссария (sticky → `overflow-x`),
закреплённая панель инструментов (`position: sticky`), шапка, `max-width` у медиа,
отсутствие `min-width` больше 320 px, прокрутка таблицы уровней списка,
мобильные правила печати. `check:render` дополнительно проверяет разметку
указателя букв в режиме чтения, его отсутствие в редакторе, наличие панели
инструментов в тесте, памятке и глоссарии и номера многоуровневого списка
(`data-list-label`) в режиме чтения.

## Шаг 17: поиск по документу

В блоках «Теория» и «Памятка» появилась панель поиска (`components/editor/DocumentSearch.jsx`):
кнопка «Поиск по документу» над слайдом или `Ctrl+F` (`Cmd+F`) — браузерный поиск
по странице здесь бесполезен, потому что на экране только один слайд. `Esc`
закрывает панель, стрелки выбирают результат, `Enter` открывает его.

Индекс не хранится: слайды теории уже загружены в `contentStore` вместе с контентом,
слайды и карточки памятки — в `memoStore`, поэтому `utils/search.js` — это проход по массиву.
Что попадает в поиск:

- название слайда (отдельный результат — открывает слайд целиком);
- название карточки памятки (отдельный результат — открывает слайд и подсвечивает карточку);
- текстовые фрагменты и «Важное» — через `docToText` из Tiptap JSON;
- таблица — все ячейки, чек-лист — заголовок и пункты;
- код — имя файла и сам код, реплика — персонаж и текст;
- картинка — `alt` и подпись, видео — подпись и ссылка.

Запрос нормализуется: нижний регистр, лишние пробелы, `ё → е`; поиск работает
с двух символов (`SEARCH_MIN_QUERY`). На фрагмент выдаётся одна строка с первым
совпадением, `makeSnippet` показывает 60 символов контекста и подсвечивает
совпадение в исходном регистре. В панели не больше 50 результатов
(`SEARCH_LIMIT`), счётчик при этом показывает все совпадения.

Клик или `Enter` переключает слайд и прокручивает к карточке (`data-memo-id` в `MemoCard`)
или фрагменту (`data-content-id` в `SlideGrid`, `MemoCard`; `scrollIntoView` после рендера
нового слайда); найденный фрагмент на 2,4 с получает класс `content-card--found`,
карточка — `is-link-target`. Панель адаптируется на телефоне: поле ввода переносится
на свою строку, сниппет обрезается до двух строк.

Проверки: `check:search` (`client/scripts/search-check.mjs`) — 53 проверки:
нормализация запроса, поля всех восьми типов контента, порядок и лимит
результатов, сниппеты, пустые данные, разметка и клавиатура панели, стили,
`data-content-id` и README. `check:render` дополнительно рендерит панель
с готовым запросом (список результатов и пустая выдача).

## Закрепление шапки и содержания

Шапка приложения (`.app-header`) закреплена вверху окна: `position: sticky;
top: 0; z-index: 40`. Уровень ниже модалок (100) и всплывающих панелей
(50–90), но выше контента и закреплённой панели инструментов (20), поэтому
меню редактора и подсказки примечаний остаются поверх шапки.

Панели, которые должны оставаться доступными при прокрутке, отступают от верха
ровно на высоту шапки — через переменную `--app-header-h`:

- `.theory__side` — «Содержание» блока «Теория» (и в редакторе, и в чтении);
- `.memo__side` — «Содержание» блока «Памятка» (та же раскладка, что у теории);
  карточки слайда — `.memo-grid` и `.memo-card`; карточки одного ряда растягиваются
  до самой высокой (`align-items: stretch`), а внутренние фрагменты не рисуют вторую
  рамку (`.memo-card .content-card`). Сетку фрагментов сбрасывает `.memo-card .slide-grid`
  (именно без `__body`: в просмотре `ContentGrid` лежит прямо в карточке, и привязка
  к обёртке редактора оставляла внутреннюю рамку — «квадрат в квадрате»). Заголовок —
  `.memo-card__title` (просмотр/печать) или `.memo-card__title-editor` (Tiptap),
  под ним `.memo-card__divider`;
- `.test-side` — «Группы» блока «Тест»;
- `.course-layout__side` — список блоков курса, `.course-layout__preview` —
  превью выбранного блока;
- `.glossary-letters` — указатель букв глоссария;
- `.toolbar` — панель инструментов редактора (`top` на 8px ниже шапки).

«Содержание», группы теста и указатель букв отступают ещё и на высоту тулбара
(см. ниже), курс и превью — только на высоту шапки.

Высота шапки не зашита константой: на узком экране она переносится на две
строки. `components/layout/Header.jsx` измеряет её `ResizeObserver` и пишет в
`document.documentElement.style.setProperty('--app-header-h', …)`; в CSS
остаётся фолбэк `64px` — на первый кадр и для SSR-рендера.

Панель инструментов растянута на всю строку и лежит над раскладкой блока, поэтому
закреплённые панели отступают ещё и на её высоту — переменная `--toolbar-h`:
`top: calc(var(--app-header-h) + var(--toolbar-h) + 16px)`. Без этого тулбар
(`z-index: 20`) при прокрутке наезжал на верх «Содержания». Высоту тоже измеряет
сам компонент — `components/editor/toolbar/Toolbar.jsx` (`ResizeObserver` и
`resize`), потому что на узком экране кнопки переносятся на вторую строку.
В режиме чтения тулбара нет, и он снимает переменную — панели возвращаются под
шапку (фолбэк в CSS — `--toolbar-h: 0px`).

Содержание прокручивается внутри панели (`max-height: calc(100vh -
var(--app-header-h) - var(--toolbar-h) - 32px); overflow-y: auto`), поэтому
длинный список слайдов не уводит панель за экран и не растягивает страницу.

На планшете и телефоне (≤900px) раскладки становятся одноколоночными, и панели
снова `position: static` — закреплять нечего; шапка закреплена на всех
размерах. Внутренние переходы и поиск не прячут цель ни под шапкой, ни под
тулбаром: у карточек контента, терминов и карточек памятки
`scroll-margin-top: calc(var(--app-header-h) + var(--toolbar-h) + 16px)`, то же
у группы глоссария.

Проверки: `check:responsive` — закрепление шапки и всех панелей, `z-index`,
измерение высоты шапки через `Header` и высоты тулбара через `Toolbar`, отступ
панелей на `--toolbar-h`, сброс закрепления на планшете, `scroll-margin-top`;
`check:render` дополнительно проверяет правила CSS шапки, отступов содержания и
того, что тулбар не наезжает на панель.
